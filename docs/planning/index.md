# planning/ — 計画書

> **このフォルダの役割**: タスクの実施計画書を置く場所。
> 進捗・状態の記録は `../task-list.md`（**唯一の正本**）に置き、計画書は個別タスクの詳細を担う。

## ここに置くもの

| ファイル | 役割 |
| :--- | :--- |
| `_TEMPLATE.md` | 計画書テンプレート（固定）。新規計画書は必ずこの形式で作成する |
| `{TOPIC}_PLAN.md` | 各タスクの実施計画書（目的 / 変更範囲 / 禁止事項 / 完了条件 / テスト方法 / 停止条件） |
| `complete/` | 完了済み計画のフォルダ |

## 使い方

1. `docs/task-list.md` に新規 ID で行を追加する
2. `_TEMPLATE.md` の形式に沿って `{TOPIC}_PLAN.md` を作成する
3. 実装が計画から外れた場合は、その差分を `../audit/diff-{context}.md` に記録する

## 運用ルール

- 計画書はタスク開始前に作成し、「ユーザーと合意した仕様の記録」として扱う。
- 命名は `{TOPIC}_PLAN.md`（トピック + `_PLAN`）。
- 完了したタスクの計画書は削除せず、`complete/` に移動する。
- Sandbox で cargo が実行できない場合は、§6.2 の代替検証 + 実機検証の分離を計画書に明記する。
- ファイル名は短く正確、ハイフン最大1つ。
